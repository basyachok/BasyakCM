# Правила и библиотека CMU в Discord

Сервер публикует игровые документы через обычные входящие вебхуки Discord. Отдельный бот не нужен.
По умолчанию публикация выключена: адреса вебхуков пустые.

## Настройка

1. В настройках Discord-канала **правила** создайте вебхук и скопируйте его URL.
2. При необходимости создайте второй вебхук в канале **руководства**.
3. Добавьте адреса в закрытый конфигурационный файл игрового сервера:

```toml
[cmu.discord]
rules_webhook = "https://discord.com/api/webhooks/ID/TOKEN"
guides_webhook = "https://discord.com/api/webhooks/ID/TOKEN"
documentation_interval = 900
```

Это примеры, а не действующие адреса. URL содержит секрет вебхука: не добавляйте заполненный
конфигурационный файл в Git. Обе настройки имеют флаг `CONFIDENTIAL` и не передаются клиентам.

Пустой `guides_webhook` отключает библиотеку; пустой `rules_webhook` отключает правила.
`documentation_interval = 0` отключает автоматическую публикацию полностью. При включении или
изменении настроек сервер ждёт 30 секунд. Затем выполняет сверку каждые 900 секунд после окончания
предыдущей; значения интервала меньше 60 секунд округляются до 60.
Изменение адресов или отключение публикации отменяет текущую отправку.

Поддерживаются текстовые каналы и существующие ветки, включая посты форума. Для ветки добавьте
к URL `?thread_id=ЧИСЛОВОЙ_ID_ВЕТКИ`. Самостоятельно создавать форумные посты система не будет.
Допускаются стандартные HTTPS-адреса `discord.com` и `discordapp.com` без дополнительных параметров.

При нескольких игровых серверах включайте публикацию только на одном сервере: он будет владельцем
копии документов. Процессы с общей папкой данных защищены общей блокировкой; разные папки данных
не знают о публикациях друг друга.

## Что появляется в каналах

**Правила:** действующий раздел `RMCOverview` и его страницы CMU: нулевая терпимость, общие и
ролевые правила, особые роли, активные режимы. Не подключённые к игровому справочнику черновики
правил не публикуются.

**Руководства:** разделы `CMUGuidebook`, `AU14SOP`, `AU14UCMJ`, `AU14CCLaw` и остальные активные
прототипы руководств с путями `/ServerInfo/Guidebook/CMU14/`, кроме правил. Обычные руководства
SS14 и независимые разделы RMC14 не включаются. XML-файлы без прототипов не публикуются.

В начале — содержание со ссылками на сообщения. Далее — цветные карточки с названиями разделов,
подзаголовками и нумерацией страниц. Правила игроков, СОП, военный и колониальный кодексы подписаны
отдельно. Длинный текст разбивается по абзацам и строкам без сокращения предложений и исключений.
Карточки ограничены 3800 символами описания и укладываются в лимиты Discord.

Текст берётся из игровых документов. Система не пересказывает правила и не использует ИИ.
Оформление и подписи локализованы через Fluent на языке сервера; язык самого XML не меняется.
Таблицы превращаются в записи с подписями колонок. Реагенты, эффекты, рецепты, снаряжение и предметы
раскрываются из игровых данных. Вместо интерактивных изображений публикуются ссылки на изображения
в репозитории; снимки игровых манекенов заменяются перечнями снаряжения.
Клавиши отображаются из поставляемого `keybinds.yml` с пометкой «по умолчанию».

У карточек есть ссылка на исходный XML в `flex5hybrid/RussianCM`, ветка `master`.
Внутренние ссылки ведут на Discord-сообщения своего раздела, когда они уже опубликованы;
при первой отправке используются ссылки на исходники, затем они заменяются ссылками на сообщения.
Ссылки на страницы за пределами выбранных документов сохраняют название ссылки обычным текстом.

## Обновление и восстановление

После изменения документа сервер редактирует прежние сообщения. Удалённые вручную сообщения
восстанавливаются, лишние страницы и убранные документы удаляются после успешной публикации
актуальной версии. Чужие сообщения каналов не затрагиваются. Правила и руководства могут
использовать один вебхук, хотя для чтения удобнее два отдельных канала.

Состояние хранится в `cmu-discord-documentation/` внутри папки данных сервера. Сохраняйте эту
папку между перезапусками, обновлениями и пересозданиями контейнера. В журнале находятся ID
сообщений, хеши содержимого и назначение `webhook_id:channel_id:thread_id`; токенов в нём нет.
Новый вебхук, канал или ветка получает отдельный журнал. Старые публикации при переносе не удаляются.
Замена токена того же вебхука сохраняет прежний журнал.

Запись заменяется атомарно после каждой операции. Лимиты запросов учитываются через `Retry-After`
и `retry_after`. Чтение, редактирование и удаление повторяются при ответах 5xx; создание повторяется
только после явного ответа 429. Ошибки одного канала не блокируют второй. Непонятный XML,
неподдерживаемый элемент или повреждённый журнал останавливают обновление соответствующего канала,
сохраняя опубликованные сообщения.

Если соединение оборвалось во время создания сообщения, Discord мог принять запрос до разрыва.
В этом случае запись остаётся с `Pending: true`, и сервер останавливает этот раздел, чтобы не
создавать дубликаты. Для восстановления:

1. Временно отключите публикацию и дождитесь сообщения об отмене либо остановите сервер.
2. Найдите соответствующий JSON-журнал по полю `Destination` и запись с `Pending: true`.
3. Если сообщение появилось в Discord, впишите его числовой ID в `Id`, установите `Pending: false`
   и очистите `Hash`. Если сообщения нет, удалите только эту запись из `Messages`.
4. Сохраните корректный JSON и снова включите публикацию.

Не удаляйте весь журнал для повторной отправки: это создаст новую копию уже опубликованных сообщений.
Обычный отказ Discord, например 403, оставляет возможность автоматического повтора после
исправления доступа. В серверном журнале выводится только код HTTP или тип ошибки, без адресов
вебхуков и тел ответов.

## Проверка

Фикстура `Content.Tests.CMU14.Discord.DocumentationPublisherTest` проверяет XML всех документов CMU,
сохранение структуры и Unicode, лимиты карточек, повторный запуск с журналом на диске, редактирование,
восстановление удалённых сообщений, разделение правил и руководств, ошибки API и неоднозначные отправки.
HTTP-запросы в тестах обрабатываются имитацией Discord и не обращаются к настоящим каналам.

Для проверки на сервере задайте вебхуки тестовых каналов, дождитесь публикации, перезапустите сервер,
измените один документ и удалите одну карточку. Должны обновиться прежние сообщения, а удалённая
карточка — восстановиться. Первый перенос библиотеки может занять несколько минут из-за лимитов Discord.
